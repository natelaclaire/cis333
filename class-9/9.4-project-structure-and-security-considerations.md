# 9.4 Project Structure and Security Considerations

In Class 8 we used the filesystem for persistence.

In Class 9, we're building web apps, which adds a new concern:

- **not every file in your project should be web-accessible**

A common security baseline for PHP projects is to use a **public web root**:

- the web server is configured so it can only serve files from a `public/` folder
- everything else (templates, helper functions, cached files, configuration) is
  kept *outside* the web root

This doesn't replace input validation or other security practices, but it
reduces the blast radius of mistakes.

## Why We Care

If your server can serve any file in your project:

- users might be able to request files you never intended to expose
- you may accidentally expose cached data, logs, config files, or source code

Even if you are careful, it is easy to make mistakes when everything is in one
web-served directory.

## New Layout: `public/` + Non-Public `app/`

For the rest of Class 9, we will use this layout:

```text
public/
  index.php
  router.php
  assets/
    app.css
    app.js
app/
  lib/
    functions.php
  partials/
    header.php
    footer.php
  pages/
    query-demo.php
    response-demo.php
    redirect-demo.php
    redirect-handler.php
    request-sources.php
    not-found.php
  storage/
    cache/
```

Key idea:

- only `public/` is meant to be served directly by the web server
- `app/` is PHP code and storage that should *not* be directly accessible by a
  URL

## Running the App (New Command)

Because our web root is now `public/`, start PHP's built-in dev server like
this:

```bash
php -S localhost:8080 -t public public/router.php
```

Then visit:

- `http://localhost:8080/`

## The Router Script (Clean URLs)

Our router script:

- serves real files from `public/` (CSS/JS)
- routes everything else based on the URL path

Examples:

- `/query` -> query string demo
- `/response` -> status code + header demo
- `/redirect` -> redirect + PRG demo
- `/sources` -> `$_SERVER` / `$_GET` / `$_POST`

This helps avoid URLs like `/pages/query-demo.php`, and it keeps `pages/` out of
public.

## The Core Security Concept

If a file is not intended to be public, do not put it in the public web root.

Examples of things that usually should *not* be public:

- `lib/` helper functions
- template partials
- storage folders (uploads, caches, logs)
- configuration files (especially those with secrets)

In frameworks, this is why you see layouts like `public/` (or `public_html/`) +
`app/`.
