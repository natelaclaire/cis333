# 9.1 Web Request/Response Basics

Chapter 10 is about how the web works.

When you build a PHP web app, your PHP code runs on the **server**, and a web
browser is the **client**. The client and server communicate by exchanging HTTP
requests and responses.

## The Big Idea: Requests and Responses

Every time you visit a page, submit a form, click a link, or load an image, the
browser sends an **HTTP request**.

A request usually includes:

- an HTTP method (like `GET` or `POST`)
- a URL (host + path + optional query string)
- request headers (metadata)
- sometimes a body (common with `POST`)

The server answers with an **HTTP response**.

A response usually includes:

- a status code (like `200` or `404`)
- response headers
- a body (HTML, JSON, an image, etc.)

PHP's job (in a typical server-rendered app) is to generate the response body
and sometimes set response headers.

## URLs: Host, Path, Query String

A URL can include:

- scheme: `https://`
- host: `example.com`
- path: `/products/123`
- query string: `?sort=price&dir=asc`

We will work with query strings in a later tutorial. For now, the key idea is
that a query string is part of the URL, and it is sent to the server with the
request.

## Status Codes (High Level)

Status codes are grouped by category:

- `2xx` success (for example `200 OK`)
- `3xx` redirects (for example `302 Found`)
- `4xx` client errors (for example `404 Not Found`)
- `5xx` server errors (for example `500 Internal Server Error`)

We'll set status codes and redirects directly from PHP later in this class.

## Project Setup: HTTP Playground

This week, we will build a small app that helps us *see* request/response
basics.

We start with `public/index.php` and display a few request details.

### Minimal Escaping Helper

When printing server-provided values into HTML, we escape them.

`app/lib/functions.php`:

```php
<?php
function h(string $value): string
{
    return htmlspecialchars($value, ENT_QUOTES, 'UTF-8');
}
```

### Reading Request Details

`public/index.php` (excerpt):

```php
<?php
$method = $_SERVER['REQUEST_METHOD'] ?? '';
$requestUri = $_SERVER['REQUEST_URI'] ?? '';
$path = parse_url($requestUri, PHP_URL_PATH);
$path = is_string($path) ? $path : '';

$queryString = $_SERVER['QUERY_STRING'] ?? '';
$host = $_SERVER['HTTP_HOST'] ?? '';
```

Then we render these values into the page using `htmlspecialchars()` (via `h()`).

## Running the App Locally

From the repository root, you can start PHP's built-in development server:

```bash
php -S localhost:8080 -t public
```

Then visit the app in your browser. Refresh the page a few times and notice:

- each refresh is a new request
- the server runs PHP again
- the response body (HTML) is regenerated

Next, we will use the browser's Developer Tools to inspect the request and
response directly.
