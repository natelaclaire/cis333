# 9.7 Redirects and Post-Redirect-Get

A **redirect** is an HTTP response that tells the browser to make a new request
to a different URL.

This is extremely common in real web apps:

- redirect from `/` to `/home`
- redirect after a successful login
- redirect after submitting a form
- redirect when a resource has moved

## Redirects in HTTP

Redirects are usually in the `3xx` range.

Common ones:

- `301 Moved Permanently`
- `302 Found` (often used for a "temporary" redirect)
- `303 See Other` (often used after a `POST`)

In a redirect response, the server includes a `Location` header. The browser
reads it and then makes a follow-up request to the new URL.

## Redirects in PHP (`header('Location: ...')`)

In PHP, redirects are usually done with `header()`:

```php
<?php
header('Location: /query');
exit;
```

Two important details:

- Call `exit;` after a redirect so the rest of the script does not continue.
- Send the redirect header before any output.

You can also pick a specific status code:

```php
<?php
header('Location: /query', true, 302);
exit;
```

Notes:

- If you use `header('Location: ...')` without specifying a status code, PHP will
  send a `302 Found` by default.
- If you want to send a different status code, you can specify it as the third
  argument to `header()`, or you can call `http_response_code()` before the
  redirect.
- The `true` second argument to `header()` means that if a `Location` header was
  already queued up, it will be replaced with this one (instead of adding a
  second `Location` header). This is the default behavior, but we're being
  explicit and using positional arguments. We could also use named arguments
  here to specifying the response code without specifying the second argument.
- Keep in mind that the second argument is **not** about the status code; it is about
  whether to replace an existing header or not - if you need multiple headers of
  the same name, you would set this to `false` and call `header()` multiple times.

## PRG: Post-Redirect-Get (High Level)

PRG is a pattern to avoid duplicate form submissions.

Without PRG:

- the user submits a form (POST)
- the server returns an HTML page (still the POST URL)
- the user presses refresh
- the browser warns about re-submitting the form (and might submit again)

With PRG:

- the user submits a form (POST)
- the server does the work (validate/save)
- the server redirects to a GET page that shows the result
- refresh only repeats the GET, not the POST

A common status code used for this redirect is `303 See Other`, which is
typically used for redirects after a POST or PUT request as it instructs
the browser to make a new request using the GET method.

## New Pages: Redirect Demo + PRG Handler

We add:

- `app/pages/redirect-demo.php`
- `app/pages/redirect-handler.php`

`redirect-demo.php` shows a few redirect examples (301/302) and includes a very
simple form.

`redirect-handler.php` processes a POST and then redirects back to a GET URL
using a 303 redirect.

Excerpt (handler):

```php
<?php
if ($_SERVER['REQUEST_METHOD'] !== 'POST') {
    http_response_code(405);
    header('Allow: POST');
    exit;
}

$qs = http_build_query(['saved' => '1', 'value' => $value]);
header('Location: /pages/redirect-demo.php?' . $qs, true, 303);
exit;
```

## Verify in DevTools

Open DevTools -> Network and click the request that triggers the redirect.

You should see:

- a `3xx` status code
- a `Location` response header
- a second request to the destination URL
