# 9.2 Using Browser DevTools to Observe HTTP

If Chapter 10 has one "superpower", it's this: you can stop guessing what the
browser and server are doing.

Browser Developer Tools let you inspect:

- the exact request the browser sent
- the exact response the server returned
- timings, caching, redirects, and errors

In this tutorial we focus on the **Network** tab.

## Setup: Run the Class 9 App

Start PHP's built-in dev server from the repository root:

```bash
php -S localhost:8000 -t class-9/app
```

Visit `http://localhost:8000/`.

## Open Developer Tools

In Chrome / Edge you can open DevTools with:

- Windows: `F12` or `Ctrl+Shift+I`
- macOS: `Cmd+Option+I`

Then open the **Network** tab.

Key checkboxes and options:

- "Preserve log" (keeps requests when you navigate)
- "Disable cache" (only works while DevTools is open)

## Capture a Request

With the Network tab open:

1. Click the **clear** button (to remove old requests).
2. Refresh the page.

You should now see multiple requests, for example:

- the document (`/`)
- a stylesheet (`/assets/app.css`)
- a script (`/assets/app.js`)

Each of these is a separate HTTP request/response.

## Read the Network Table

The Network table typically shows columns like:

- **Name**: the requested path
- **Status**: HTTP status code (200, 404, 304, ...)
- **Type**: document, stylesheet, script, image, fetch/xhr, ...
- **Initiator**: what caused the request (parser, script, ...)
- **Size**: transferred bytes vs resource size
- **Time** and **Waterfall**: timing breakdown

Click the request for `/` (the document) to see detailed panels.

## Headers: General, Request Headers, Response Headers

In the request detail view, open **Headers**.

The most important sections are:

### General

- Request URL
- Request Method (`GET` for a normal page load)
- Status Code (`200 OK` for a successful page)

### Request Headers (Client -> Server)

Headers are metadata the browser sends to the server.

Examples you will commonly see:

- `Host`
- `User-Agent`
- `Accept`
- `Accept-Language`
- `Cookie` (after you start working with sessions/logins)

### Response Headers (Server -> Client)

Headers are metadata the server sends back.

Examples you will commonly see:

- `Content-Type` (HTML, JSON, CSS, ...)
- `Content-Length`
- `Cache-Control`

Later in this class, we'll set response headers and status codes from PHP using
`header()` and `http_response_code()`.

## Response Body: Preview vs Response

Most browsers provide a **Preview** tab and a **Response** tab:

- **Preview** tries to render/format the response.
- **Response** shows the raw body.

For our homepage, the response body is HTML.

## Try These Experiments

### 1) Query strings

Visit:

- `http://localhost:8000/?name=Nate`

In the Network details for the document request:

- confirm the Request URL includes the query string
- confirm the Request Method is still `GET`

### 2) Trigger a 404

Visit a path that does not exist:

- `http://localhost:8000/does-not-exist`

Then check the Network entry:

- Status should be `404` (or `404 Not Found`)
- Response body will likely be a simple text message from the dev server

### 3) Caching behavior

With DevTools open:

- toggle "Disable cache" on and off
- refresh several times

Watch for changes in the **Size** column. When caching is enabled, browsers may
reuse resources.

Not all caching scenarios show up in the same way, but this is a good habit:
when something looks "stuck" in a web app, check the Network tab.

## The Mental Model to Keep

- A web page is not one thing.
- It is a collection of requests: HTML, CSS, JavaScript, images, and more.
- The Network tab is your source of truth for what the browser actually did.
