# 9.3 Simple Routing with REQUEST_URI

So far, our app has been a collection of PHP files under `pages/`.

That is a totally valid approach for small projects, but most web apps quickly
want something more structured:

- one entrypoint
- a set of routes (URL paths) that map to handlers
- shared logic in one place (auth, logging, error handling)

That idea is called **routing**.

In this tutorial we will implement a tiny router using the PHP built-in dev
server.

## What Is a Route?

A **route** is a mapping from a request (usually the method + path) to some code
that generates a response.

Examples:

- `GET /` -> home page
- `GET /query` -> query string demo
- `GET /response` -> response header/status demo

Frameworks do this for you, but it's useful to understand the basics.

## The Key Input: $_SERVER['REQUEST_URI']

`$_SERVER['REQUEST_URI']` contains the path and query string.

Example values:

- `/query`
- `/query?name=Nate`

We usually use `parse_url()` to extract the path:

```php
<?php
$uri = $_SERVER['REQUEST_URI'] ?? '/';
$path = parse_url($uri, PHP_URL_PATH);
$path = is_string($path) ? $path : '/';
```

## Dev Server Router Script

PHP's built-in server supports a special "router script".

From the repository root, start the server like this:

```bash
php -S localhost:8080 -t public public/router.php
```

With a router script, you can:

- serve static files normally (CSS/JS/images)
- route everything else based on the URL path

## Router Implementation

We add `public/router.php`.

Key ideas:

1. If the request is for a real file (like `/assets/app.css`), let the server
   serve it directly.
2. Otherwise, map the URL path to a PHP handler.
3. If no route matches, return a 404 page.

Excerpt:

```php
<?php
$fullPath = __DIR__ . $path;
if (is_file($fullPath)) {
    return false;
}

$routes = [
    '/' => __DIR__ . '/index.php',
    '/query' => __DIR__ . '/pages/query-demo.php',
];

$target = $routes[$path] ?? __DIR__ . '/pages/not-found.php';
require $target;
return true;
```

## Try It

With the router script running, visit:

- `http://localhost:8080/query`
- `http://localhost:8080/response`
- `http://localhost:8080/redirect`
- `http://localhost:8080/sources`

- `http://localhost:8080/does-not-exist`

## How This Relates to MVC

A common organization pattern is **MVC**:

- Model: data and business logic
- View: templates / HTML
- Controller: request handling and routing decisions

Our router script is a tiny example of the controller layer: it receives a
request and decides what code should run.
