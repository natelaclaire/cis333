# 9.10 Remote Data and Caching

In web development, you'll often need to use data that lives somewhere else:

- a public dataset
- a partner API
- a microservice your own team runs

When remote data is involved, two things become true:

- remote resources can be slow or unreliable
- you should avoid re-downloading the same thing on every request

A common solution is **caching**.

## What We Mean by Caching

Caching means storing a computed result so it can be reused.

In this tutorial we cache on disk:

- download a remote CSV file
- generate an HTML table
- write the generated HTML to a cache file
- on the next request, serve the cached HTML if it is still "fresh"

## Cache Freshness (TTL)

A cache is only useful if you can decide when it is too old.

A common approach is a TTL (time-to-live):

- if cache age <= TTL, use cache
- otherwise, refresh

In PHP:

- `time()` returns the current time (Unix timestamp)
- `filemtime($path)` returns the last modified time of a file

So cache age is:

```php
<?php
$ageSeconds = time() - filemtime($cacheFile);
```

## New Page: Remote Data + Caching Demo

We add:

- `app/pages/remote-cache-demo.php`

And route it as:

- `/remote-cache`

This page:

- downloads a remote CSV using `fopen()` + `fgetcsv()`
- generates a small HTML table (limited to a number of rows)
- caches the rendered HTML to `app/storage/cache/`
- uses the cached HTML when it is still within the TTL

The page also supports a simple query string control:

- `?refresh=1` to ignore the cache and force a refresh

## Building HTML in a String

To cache generated output, you need to build the HTML in a variable.

One simple technique is output buffering:

```php
<?php
ob_start();
print '<p>Hello</p>';
$html = ob_get_clean();
```

`ob_start()` starts buffering output, and `ob_get_clean()` gets the
buffered output and ends buffering without directly outputting it (it
cleans the output from the buffer). After this code runs, `$html`
contains the string `'<p>Hello</p>'`.

Then you can write `$html` to a cache file with `file_put_contents()`.

[Output buffering](https://notlaura.com/output-buffering/) is a powerful
technique that allows you to capture any output that would normally be
sent to the browser and instead store it in a variable. This is
especially useful when generating complex HTML that is easier to write
with `print` or `echo` statements rather than concatenating strings.

## File Locking (Basic)

If multiple requests try to write the cache at the same time, you can get
partially-written files.

For basic safety, use `LOCK_EX` to acquire an exclusive lock when writing:

```php
<?php
file_put_contents($cacheFile, $html, LOCK_EX);
```

## Verify in DevTools

Open DevTools -> Network and compare requests:

- first load (or forced refresh) may be slower
- later loads should be faster when the response is built from the cache

This is the same client-server process as before; caching changes what the
server does to generate the response.
