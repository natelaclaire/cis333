# 8.1 Project Setup and Reading a File

In Class 8, we start Chapter 9 by building a small file-based web app. For
this first tutorial, we are not using forms. We will read a sample note from
disk and display it in the browser.

## App Structure

We start with a small folder structure:

```text
lib/
  functions.php
public/
  pages/
  index.php
partials/
  header.php
  footer.php
storage/
  notes/
    welcome.txt
```

The `storage/notes/` folder is where our note files live.

For security purposes, we will not serve files directly from `storage/`. Instead, we read the file contents in PHP and print it into our HTML. This is a common pattern for file-based apps: the web server only serves PHP files, and the PHP code reads and writes data files as needed. This allows us to control access and to do things like escaping file contents for safe display.

We're also going to move any files that aren't served directly out of the `public/` folder, which is a good security practice. Consequently, `lib`, `partials`, and `storage` are all outside of `public/`. In a few weeks, we'll explore a more advanced setup where `index.php` acts as a front controller that routes all requests and therefore is the only file in `public/`, but for now we will keep it simple.

## Reading a File into a String

Chapter 9 introduces `file_get_contents()` for reading an entire file into a
string.

In `public/index.php`, we build a file path using `__DIR__` and read the
note:

```php
<?php
$noteText = file_get_contents($noteFile);
```

`file_get_contents()` returns the file contents as a string. If it fails, it
returns `false`.

## Displaying File Contents Safely in HTML

When you print file contents into a web page, escape it so that any
characters like `<` and `>` are treated as text.

In `public/index.php`, we use `htmlspecialchars()`:

```php
<pre><?php print htmlspecialchars($noteText === false ? '' : $noteText, ENT_QUOTES, 'UTF-8'); ?></pre>
```

Next, we will improve this by confirming that files and directories exist
before reading and by creating them when appropriate.
