# 12.10 Class 12 Reinforcement Exercises

These exercises are intentionally simple and focus on the Class 12 concepts:

- Composer-managed libraries (YAML + Markdown parsing)
- Apache rewriting with `.htaccess`
- YAML-driven configuration (nav)
- Markdown content pages + YAML front matter metadata
- contact form submissions saved to a TSV file

All exercises build on the existing project.

## Exercise 12-1: Add a New Markdown Page + Nav Link

Goal: practice Markdown + YAML front matter and YAML-driven navigation.

Tasks:

- Create a new Markdown page:
  - `app/content/pages/privacy-policy.md`
- Add YAML front matter with at least:
  - `title`
  - `description`
  - `robots`
- Add a new nav entry for the slug `privacy-policy` in:
  - `app/config/config.yml`
- You do NOT need to update the front controller or add a new route case for this page
  because the layout already handles dynamic pages based on Markdown files in the `pages`
  directory.

## Exercise 12-2: Add a New Metadata Field (Twitter Card)

Goal: practice extending the layout metadata system safely.

Tasks:

- [Learn more about the Twitter Card markup](https://www.digitalocean.com/community/tutorials/how-to-add-twitter-card-and-open-graph-social-metadata-to-your-webpage-with-html)
- Add a new YAML front matter field named `twitterCard` to:
  - `app/content/pages/faqs.md`
  - Suggested value: `"summary_large_image"`
- Update the layout head template to output it if present:
  - `app/views/partials/header.php`
  - Example tag:
    - `<meta name="twitter:card" content="...">`

Rule:

- Escape the value when printing it into HTML.

## Exercise 12-3: Add a `subject` Field to the Contact Form

Goal: practice the field spec pattern and server-side validation rules.

Tasks:

- Add a `subject` field to the contact form spec:
  - `app/lib/fields.php`
- Suggested requirements:
  - required
  - minLength 3
  - maxLength 120
- Add HTML5 UX attributes (required, minlength, maxlength).

Note:

- TSV storage derives columns from `contactFields()`, so the new field should automatically appear in new TSV rows.

## Exercise 12-4: Create a Contact Submissions Viewer Page

Goal: practice reading a TSV file and rendering safely in HTML.

Tasks:

- Add a new PHP page template:
  - `app/views/pages/contact-submissions.php`
- Add a new route case in the front controller:
  - `public/index.php`
  - Slug: `contact-submissions`
- The page should:
  - use `fgetcsv` to read `app/storage/contacts.tsv` (override the default comma delimiter with a tab character)
  - display the most recent 10 submissions in a table
  - escape values before printing into HTML
  - show a friendly message if the TSV file does not exist yet

**Note:** In a real app, you would never display raw contact submissions like this without authentication and proper
security measures. This exercise is just for practice with TSV file reading and HTML output. The fact that this isn't
in the navigation and has a non-obvious URL is NOT true security - NEVER do this in a production environment!

## Exercise 12-5: Redirect `/home` to `/` in `.htaccess`

Goal: practice the difference between internal rewrites and redirects.

Tasks:

- Update:
  - `public/.htaccess`
- Add a redirect rule so that:
  - `/home` redirects to `/`
- Use a 301 redirect (permanent) status code like this:

```
RewriteRule ^/home$ / [R=301,L]
```

Tip:

- Place the redirect rule before the “send everything to index.php” rewrite rule.
