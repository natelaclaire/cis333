# 12.3 Our Front Controller (`public/index.php`)

In 12.2 we used Apache rewriting to route clean URLs like `/contact-us` to a single entry point:

- `public/index.php`

That single entry point is called the **front controller**.

In this tutorial we’ll walk through how our `index.php` is set up and what that implies for local development.

## What the Front Controller Does

In a server-rendered PHP app, the front controller usually has three jobs:

1. **Bootstrap** the app (autoload, constants, configuration, shared helpers).
2. **Route** the request (decide which page/controller to run).
3. **Render** the response (templates/layout, 404 handling, etc.).

Our starter file does all three in a simple and readable way.

## Step 1: Define the Application Root

At the top of `public/index.php` we define a constant that points to the app root folder:

```php
<?php
define('APP_PATH', __DIR__ . '/../');
```

This makes it easy to require files using absolute paths relative to the project:

- `APP_PATH . 'app/lib/functions.php'`

## Step 2: Bootstrap: Composer Autoload + App Helpers

Next, the file loads Composer’s autoloader:

```php
<?php
require APP_PATH . 'vendor/autoload.php';
```

This enables:

- third-party packages installed by Composer
- any PSR-4 autoloading for your own classes (if configured)

Then it includes application helpers:

```php
<?php
require_once APP_PATH . 'app/lib/functions.php';
require_once APP_PATH . 'app/lib/storage.php';
```

## Step 3: Load Configuration

The starter loads config early:

```php
<?php
$config = loadConfig();
```

This makes config available to downstream helpers and templates.

## Step 4: Determine “Which Page?” Using a Query Parameter

Because Apache rewrites clean URLs to:

- `index.php?page=<slug>`

our front controller reads the page slug from the query string:

```php
<?php
$page = getString('page');
```

Then it normalizes/sanitizes it so it’s safe to use in routing logic:

- trim
- lowercase
- replace `_` with `-`
- remove slashes, spaces, and other potentially dangerous characters

The key idea:

- even though the URL looks like `/services`, the server-side “routing input” is still user-controlled input.

## Step 5: Route With a `switch`

The starter uses a `switch` statement to map page slugs to PHP templates:

```php
<?php
switch ($page) {
    case '':
        include APP_PATH . 'app/views/pages/home.php';
        break;
    case 'services':
        include APP_PATH . 'app/views/pages/services.php';
        break;
    // ...
    default:
        // 404 or markdown page
}
```

This is a simple, explicit routing approach that works well for small apps.

## Step 6: Output Buffering + Layout

The file uses output buffering so it can:

- generate page content first
- then wrap it in a shared layout (header/footer)

High level:

```php
<?php
ob_start();
// include page template(s)
$pageContent = ob_get_clean();

include APP_PATH . 'app/views/partials/header.php';
echo $pageContent;
include APP_PATH . 'app/views/partials/footer.php';
```

This keeps templates simpler because:

- page templates can just print content
- the layout handles the outer HTML structure
- if any pages want to set variables for the layout (e.g. page title) or send headers, they can do that before the header include

## Local Development: Why This `index.php` Is Not a PHP Dev Server Router

PHP’s built-in dev server supports a “router script”, but it works by inspecting the request URI:

- `$_SERVER['REQUEST_URI']`

In our earlier apps (Classes 9–11), we used a router script that mapped paths like `/courses/new` directly.

This starter app is different:

- it expects Apache rewriting to populate `page=...` in the query string
- it does *not* route directly from the raw path

That means:

- `public/index.php` is a front controller for Apache, not a dev-server router script.

If you run:

```bash
php -S localhost:8080 -t class-12/starter-files/public
```

and then visit `/contact-us`, PHP will request `/contact-us` as a file path:

- there is no `.htaccess` processing
- no rewrite happens
- `page` will be missing

So your clean URLs will not work the same way under `php -S`.

To test clean URLs, you need Apache (or another server) that applies the rewrite rules.
