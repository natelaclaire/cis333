# 12.5 Markdown Basics (And How We Render It)

This week’s starter project uses **Markdown** as a simple “content format” for pages like:

- About Us
- FAQs

Markdown lets you write content in plain text with lightweight formatting and then convert it into HTML.

In this tutorial we’ll cover:

- what Markdown is (and the basics you need)
- how we’re using it in this project
- which library we use to convert Markdown to HTML

## What Markdown Is

Markdown is a plain-text markup format that’s designed to be easy to write and read.

You write something like:

```md
# Heading

This is **bold** and this is a list:

- item one
- item two
```

And a Markdown parser converts it to HTML:

- `#` becomes `<h1>`
- `**bold**` becomes `<strong>`
- list items become `<ul><li>...</li></ul>`

## Markdown Basics (Common Syntax)

Headings:

```md
# H1
## H2
### H3
```

Emphasis:

```md
**bold**
*italic*
```

Links:

```md
[Example](https://example.com)
```

Lists:

```md
- bullet
- bullet
```

That’s enough syntax for most “content pages”.

## How We Use Markdown in This Project

Markdown content pages live in:

- `app/content/pages/`

Examples:

- `about-us.md`
- `faqs.md`

These files have two parts:

1. **YAML front matter** at the top (metadata like title/description)
2. **Markdown content** after the front matter

Example (trimmed):

```md
---
title: "About Us"
classes: "about-page"
---

# About Us

Business Name was founded in 2019...
```

## The Markdown Library We Use: Parsedown

We convert Markdown to HTML using a Composer-installed library:

- `erusev/parsedown`

It’s declared in:

- `composer.json`

And is available because `public/index.php` includes:

```php
<?php
require APP_PATH . 'vendor/autoload.php';
```

In code, the starter uses Parsedown like this:

```php
<?php
$parsedown = new Parsedown();
$html = $parsedown->text($markdown);
```

You can see that inside:

- `class-12/starter-files/app/lib/functions.php` (`fetchPage()`)

## A Security Note: Markdown Rendering and XSS

Markdown is not automatically “safe”.

Depending on the parser and configuration, it may allow raw HTML inside Markdown.

That means:

- If *users* can edit Markdown, you must treat it as untrusted input.
- You may need to disable HTML, sanitize output, or use a different strategy.

In our class project:

- Markdown files live in the repository (developer-controlled content)
- so we can treat them as trusted content **for this course**

But the principle remains:

- any time untrusted input can reach HTML, you must think about XSS.
