# 12.8 YAML Front Matter, Layout Metadata, and SEO Tags

In 12.7 we looked at how the app chooses between PHP pages and Markdown content pages.

In this tutorial we focus on **metadata**:

- how YAML front matter provides structured page metadata
- how the layout uses that metadata to render SEO and social sharing tags
- how to keep the system safe and maintainable

## What “Metadata” Means Here

Metadata is “data about the page” that isn’t the page’s main content.

Common metadata includes:

- `title` (browser tab + SEO)
- `description` (SEO snippet)
- `robots` (indexing rules)
- canonical URL
- Open Graph (OG) tags (Facebook/LinkedIn previews)

In our starter, metadata is stored as YAML in the page front matter.

## YAML Front Matter in Markdown Pages

Markdown pages in:

- `app/content/pages/`

start with YAML front matter, separated by `---`.

Example (trimmed from `faqs.md`):

```yaml
---
title: "Frequently Asked Questions"
classes: "faqs"
description: "Get clear answers to common questions..."
robots: "all"
ogTitle: "Business Name Frequently Asked Questions"
ogType: "website"
ogImage: "/images/portfolio-thumbnails/example.png"
ogDescription: "Get clear answers to common questions..."
---
```

## How Front Matter Becomes `$pageInfo`

When a Markdown page is requested, `fetchPage()`:

1. reads the `.md` file
2. splits YAML and Markdown
3. parses YAML into an associative array (`$pageInfo`)
4. converts Markdown to HTML and stores it in `$pageInfo['content']`

The result looks like:

```php
<?php
$pageInfo = [
  'title' => 'Frequently Asked Questions',
  'description' => '...',
  'robots' => 'all',
  'ogTitle' => '...',
  'content' => '<h1>...</h1> ...',
];
```

For PHP pages (like `services.php`), the front controller sets metadata manually:

```php
<?php
$pageInfo['title'] = 'Services';
```

This is a nice hybrid approach:

- Markdown pages carry their own metadata in YAML
- PHP pages can set metadata in code

## Where Metadata Is Used: The Layout Header

The HTML `<head>` section lives in:

- `app/views/partials/header.php`

This file uses `$pageInfo` to render SEO and OG tags:

- `<title>`
- `<link rel="canonical">`
- `<meta name="description">`
- `<meta name="robots">`
- `<meta property="og:*">`

For example:

- it prefers `ogTitle` if present, otherwise it falls back to `title`
- it prefers `ogDescription` if present, otherwise falls back to `description`

## Canonical URLs and Why They Matter

The canonical URL tells search engines what the “main” URL for a page is.

This helps avoid duplicate content issues when the same page can be reached through multiple URLs.

In the starter:

- if a page defines `canonical`, that value is used
- otherwise the app constructs one based on the current host + page URL

## Keeping This Safe

Even though front matter is in repository files for this class, treat the output as untrusted by default.

Risks include:

- XSS if metadata is ever user-controlled
- broken HTML if quotes are not escaped

That’s why the layout uses escaping functions like:

- `htmlentities(...)`
- `htmlspecialchars(...)`

Rule:

- Any time you print metadata into HTML, escape it.

Also be careful with URLs:

- don’t blindly trust a `canonical` value from untrusted sources
- if users can edit metadata, you should validate/allowlist domains or paths

## Keeping This Maintainable

The maintainability goal is “one layout, many pages”.

Helpful patterns:

- Use consistent front matter keys across pages (`title`, `description`, `robots`, `ogImage`, etc.)
- Set defaults and fallbacks in the layout (as this starter does)
- Keep page templates focused on content; keep `<head>` logic centralized in the layout partial

If you add a new metadata feature:

- add it to the layout once
- then pages can opt into it via YAML
