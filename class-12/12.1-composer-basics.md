# 12.1 Composer Basics

This week we are going to use third-party libraries in PHP, and in modern PHP that almost always means using
**Composer**.

Composer is PHP's dependency manager. It helps you:

- declare which packages your project depends on
- install and update those packages reproducibly
- automatically load package classes with an autoloader

This is something we'll be using extensively in CIS 334, but for now we'll just cover the basics of how
Composer works and how to use it in a project.

## The Problem Composer Solves

Without Composer, using a library often turns into:

- downloading ZIP files manually
- copying code into your project
- figuring out which file to `require` first
- fighting version conflicts between libraries

Composer replaces that with a standard workflow and a standard project layout.

## The Two Key Files: `composer.json` and `composer.lock`

### `composer.json`

`composer.json` is where your project declares dependencies and configuration.

Example (from this week's starter files):

```json
{
  "require": {
    "phpmailer/phpmailer": "^6.9",
    "erusev/parsedown": "^1.7",
    "symfony/yaml": "^7.2"
  },
  "autoload": {
    "psr-4": {
      "App\\": "classes/"
    }
  }
}
```

### `composer.lock`

`composer.lock` records the exact package versions that were installed.

This is what makes installs reproducible:

- `composer install` installs the exact versions in `composer.lock`
- `composer update` chooses newer versions (within constraints) and updates `composer.lock`

## Installing Dependencies

In a project folder containing `composer.json`:

```bash
composer install
```

This will typically create:

- `vendor/` (downloaded packages)
- `vendor/autoload.php` (Composer's autoloader)

## Autoloading: `vendor/autoload.php`

Instead of manually `require`-ing dozens of library files, you include a single file:

```php
<?php
require __DIR__ . '/../vendor/autoload.php';
```

In the class-12 starter, this happens in:

- `public/index.php`

Composer also supports autoloading **your own** classes, but we'll explore that in CIS 334.

## Common Composer Commands

Create/update dependencies:

```bash
composer require vendor/package
composer remove vendor/package
composer update
composer install
```

Inspect dependencies:

```bash
composer show
composer outdated
```

Autoload troubleshooting:

```bash
composer dump-autoload
```

Security checks (when available in your Composer version):

```bash
composer audit
```

## Version Constraints (Why `^6.9` Matters)

Composer uses version constraints to control what updates are allowed.

The caret operator is very common:

- `^6.9` generally means "allow compatible updates in the same major version"

So Composer can update `6.9.x` to newer `6.x` versions without jumping to `7.x` automatically.

## What to Commit

In most PHP projects, you typically commit:

- `composer.json`
- `composer.lock`

And you do **not** commit:

- `vendor/`

Instead, anyone who clones the project runs `composer install` to recreate `vendor/`.
