# 12.6 YAML-Driven Navigation

In 12.4 we introduced YAML and showed how we load `config.yml`.

In this tutorial we focus on one practical payoff:

- our site navigation (the top menu) is driven by YAML config instead of hard-coded HTML.

## Why Drive Navigation From Config?

If navigation is hard-coded in templates, changing it can be annoying and error-prone:

- you might have to update multiple templates
- it’s easy to forget to add/remove a link in one place

By moving navigation to a config file:

- you change links in one place (`config.yml`)
- templates just render whatever the config says

## The YAML Config: `app/config/config.yml`

Navigation is defined in:

- `class-12/starter-files/app/config/config.yml`

In YAML, navigation is a list (a sequence):

```yaml
nav:
  - title: "Home"
    url: ""
  - title: "Services"
    url: "services"
  - title: "Contact Us"
    url: "contact-us"
```

Each nav item is a mapping with two keys:

- `title` (what the user sees)
- `url` (the page slug)

## Loading Config Into `$config`

In our front controller:

- `class-12/starter-files/public/index.php`

we do:

```php
<?php
$config = loadConfig();
```

`loadConfig()` uses Symfony YAML to parse the YAML into a PHP array:

- `class-12/starter-files/app/lib/functions.php`

At runtime, `$config['nav']` becomes a PHP array like:

```php
<?php
[
  ['title' => 'Home', 'url' => ''],
  ['title' => 'Services', 'url' => 'services'],
]
```

## Rendering Navigation: Looping Over `$config['nav']`

The nav template lives at:

- `class-12/starter-files/app/views/partials/main-navigation.php`

It loops over the config and prints each link:

```php
<?php
foreach ($config['nav'] as $nav) {
    $url = constructUrl($nav['url']);
    // print <a href="...">...</a>
}
```

Two key ideas:

1. We are not hard-coding `<a>` tags for each page.
2. We escape the link title when rendering:
   - `htmlspecialchars($nav['title'])`

Even though config is developer-controlled for this class, escaping is still the default best practice.

## How Link URLs Are Built: `constructUrl()`

Rather than hard-coding the query string format everywhere, we use a helper:

- `constructUrl()` in `class-12/starter-files/app/lib/functions.php`

It uses `baseUrl` from config:

```yaml
baseUrl: "/index.php?page="
```

So:

- `constructUrl('services')` returns `/index.php?page=services`

And:

- `constructUrl('')` returns `/` for the home page

This keeps URL-building consistent and makes it easy to change your URL strategy later.

## Highlighting the “Active” Link

The nav partial compares:

- the current request URL (`$_SERVER['REQUEST_URI']`)
- the URL it’s about to render

If they match, it applies Bootstrap’s “active” styling.

This is a small but important UX detail: the user can see which page they’re on.
