# 12.7 PHP Pages vs Markdown Content Pages

In this starter project, not every page is a `.php` file.

We support two kinds of pages:

1. **PHP pages** (templates that can run logic)
2. **Markdown content pages** (content-first pages with YAML front matter)

This tutorial explains how the system decides which one to render.

## The Two Page Types

### PHP Pages

PHP pages live in:

- `app/views/pages/`

Examples:

- `home.php`
- `services.php`
- `portfolio.php`
- `contact-us.php`

These are “full power” pages:

- they can load data
- run validation
- call libraries
- include partials

### Markdown Content Pages

Markdown pages live in:

- `app/content/pages/`

Examples:

- `about-us.md`
- `faqs.md`

These files are content-first:

- YAML front matter provides metadata (title, description, etc.)
- Markdown provides the page content

They are rendered into HTML using:

- Symfony YAML (`symfony/yaml`)
- Parsedown (`erusev/parsedown`)

## The Input That Drives Routing: `page`

Because of Apache rewriting, requests like:

- `/services`
- `/about-us`

are rewritten to:

- `index.php?page=services`
- `index.php?page=about-us`

So the front controller (`public/index.php`) reads:

```php
<?php
$page = getString('page');
```

Then it normalizes/sanitizes it (lowercase, remove unsafe characters).

## Routing Logic in `public/index.php`

The decision happens inside a `switch`:

- known slugs map to PHP templates
- unknown slugs fall through to “maybe it’s a Markdown page”

High-level:

```php
<?php
switch ($page) {
  case '':
    include APP_PATH . 'app/views/pages/home.php';
    break;
  case 'services':
    include APP_PATH . 'app/views/pages/services.php';
    break;
  default:
    // markdown page or 404
}
```

## How We Detect Markdown Pages: `validPage()`

In the `default` case, we check whether there is a matching Markdown file:

```php
<?php
if (validPage($page)) {
    $pageInfo = fetchPage($page);
    echo $pageInfo['content'];
} else {
    http_response_code(404);
    include APP_PATH . 'app/views/errors/404.php';
}
```

`validPage()`:

- scans `app/content/pages/`
- builds a list of available filenames
- checks whether `<slug>.md` exists in that list

This matters for safety:

- We are not taking user input and blindly doing `include($page . '.php')`.
- We only serve Markdown files that actually exist in the content folder.

## How Markdown Pages Are Rendered: `fetchPage()`

When a Markdown page exists, `fetchPage()`:

1. reads the `.md` file as a string
2. splits YAML front matter from Markdown content
3. parses YAML into `$pageInfo` (an array)
4. converts Markdown to HTML and stores it under `$pageInfo['content']`

That means Markdown pages can contribute both:

- metadata (used by the `<head>` template)
- content HTML (printed into the layout)

## Why We Use Both (PHP and Markdown)

This hybrid approach is common in small sites:

- PHP pages are best when you need logic (forms, data, dynamic pages)
- Markdown pages are best when you want simple editable content

It’s a nice balance between “CMS” and “hard-coded templates”.
