# 12.4 YAML Basics (And How We Parse It)

This week’s starter project uses **YAML** in three places:

1. A site configuration file (`app/config/config.yml`)
2. YAML “front matter” at the top of Markdown pages (metadata like title/description)
3. YAML files for content management

This tutorial is a quick, practical introduction to YAML and how we handle it in PHP.

## What YAML Is

YAML is a human-friendly data format (similar in spirit to JSON) that’s designed to be easy to read and write.

YAML is commonly used for:

- configuration files
- content metadata

## YAML Basics (The Only Pieces You Usually Need)

### Mappings (Key/Value Pairs)

This:

```yaml
baseUrl: "/index.php?page="
```

becomes an associative array in PHP:

```php
<?php
[
  'baseUrl' => '/index.php?page='
]
```

### Sequences (Lists)

This:

```yaml
nav:
  - title: "Home"
    url: ""
  - title: "Services"
    url: "services"
```

becomes a nested array in PHP (a list of associative arrays):

```php
<?php
[
  'nav' => [
    ['title' => 'Home', 'url' => ''],
    ['title' => 'Services', 'url' => 'services'],
  ]
]
```

### Indentation Matters

YAML uses indentation to represent structure.

Two common rules:

- use spaces (not tabs)
- be consistent (2 spaces is common)

If indentation is wrong, YAML parsing fails or produces unexpected structure.

## Where YAML Lives in Our Starter

### Config File

Config lives in:

- `class-12/starter-files/app/config/config.yml`

It contains values like:

- `baseUrl` (used to construct links)
- `nav` (used to render navigation)

### YAML Front Matter (Metadata)

Some content files begin with YAML at the top, separated from content with `---`.

This is often used for metadata:

- title
- description
- canonical URL
- robots settings
- Open Graph (OG) tags

In our starter, a helper function reads a Markdown file and splits:

- YAML metadata
- Markdown content

Then it parses YAML into an array and Markdown into HTML.

We'll discuss Markdown in the next tutorial.

## How We Parse YAML: Symfony YAML (Composer Library)

We do not parse YAML ourselves.

We use a Composer-installed package:

- `symfony/yaml`

It is declared in:

- `class-12/starter-files/composer.json`

Composer makes the YAML parser available through the autoloader:

```php
<?php
require APP_PATH . 'vendor/autoload.php';
```

Then we can use it like:

```php
<?php
use Symfony\Component\Yaml\Yaml;

$config = Yaml::parseFile(APP_PATH . 'app/config/config.yml');
```

In the starter, `loadConfig()` does exactly that:

- `class-12/starter-files/app/lib/functions.php`

## YAML Safety Notes

YAML is “just data”, but a few rules still apply:

- Treat YAML input as untrusted if it can be edited by users.
- Prefer parsing YAML you control (config files in your repo).
- Always escape on output when rendering strings into HTML (XSS prevention).
