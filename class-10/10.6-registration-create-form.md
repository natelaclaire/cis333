# 10.6 Registration Create Form

Now that we can create, edit, and delete **courses**, we can start tracking the second part of our app:

- student registrations for courses

In this tutorial we build the **Create** part of CRUD for registrations.

## New Routes

- `GET /registrations` (list registrations)
- `GET /registrations/new` (registration form)
- `POST /registrations/create` (process form)

Files:

- `class-10/course-registration/app/views/pages/registrations-index.php`
- `class-10/course-registration/app/views/pages/registrations-new.php`
- `class-10/course-registration/app/views/pages/registrations-create.php`

## Input Types We Practice

This form gives practice with multiple input types:

- text input: `studentName`
- email input: `studentEmail`
- date input: `birthDate`
- select dropdown: `courseId`
- radio buttons: `status` (`credit` vs `audit`)
- checkboxes: `newsletter`, `acceptedPolicy`

## The Key Challenge: Choosing a Course

Each registration must reference a course.

We use a `<select>` where each option value is the course ID:

```php
<select name="courseId">
  <option value="c_abc123">CIS333 - Server-Side Programming</option>
</select>
```

In PHP, we store the chosen course ID on the registration:

```php
[
  'courseId' => $courseId,
  'studentName' => $studentName,
  // ...
]
```

## Processing POST Data (Using `filter_input()`)

As in the book, we prefer `filter_input()` over reading `$_POST` directly.
In our project we call `filter_input()` through helper functions like `postString()` and `postBool()`.

Example:

```php
<?php
$studentName = trim(postString('studentName'));
$courseId = postString('courseId');

$acceptedPolicy = postBool('acceptedPolicy'); // checkbox (missing when unchecked)
```

After we append the new registration to `$data['registrations']`, we save JSON and redirect:

```php
<?php
saveData($data);
header('Location: /registrations?created=1', true, 303);
exit;
```
