# 10.7 Registration List and Remove

We can now create registrations. Next we need two practical features:

- a list page that we can filter by course
- a way to remove a registration (Delete)

## Filtering with GET

Filtering is a great fit for `GET` because:

- the filter becomes part of the URL (`?courseId=...`)
- you can bookmark/share the filtered view
- refreshing is safe

In `GET /registrations` we add a small filter form:

- `method="get"`
- a `<select name="courseId">` populated from stored courses

When the form is submitted, PHP reads the filter from the query string and we only display matching registrations.

## Removing a Registration (POST-only)

Just like course delete, we do not delete via GET.

We add a small form next to each registration:

```html
<form method="post" action="/registrations/delete">
  <input type="hidden" name="id" value="r_abc123">
  <button type="submit">Remove</button>
</form>
```

The handler:

- confirms the request method is POST
- retrieves the registration id using `filter_input()` (via `postString()`)
- removes that registration from the `registrations` array
- saves JSON
- redirects back to `/registrations?deleted=1` (PRG)

## Preserving the Filter After Delete

If the user is looking at:

- `/registrations?courseId=c_abc123`

and they click remove, it is nicer to redirect back to the same filtered view.

We do that by including a hidden `courseId` in the remove form and adding it to the redirect query string.
