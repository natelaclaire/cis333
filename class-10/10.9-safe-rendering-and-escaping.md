# 10.9 Safe Rendering (Escaping User Input)

Any time your PHP app displays something that came from a user (a form, a query string, a file, a database),
you must think about **output escaping**.

This tutorial focuses on the most common web security issue in forms-based apps:

- **XSS** (Cross-Site Scripting)

## The Core Idea

When you place untrusted data into HTML, the browser will interpret it as HTML.

If you do not escape, a malicious user can inject markup and JavaScript.

Example of a dangerous input:

```text
<script>alert('XSS')</script>
```

If you print that directly into an HTML page, the browser will execute it.

## Escape on Output (Not on Input)

A useful rule for this course:

- store the raw string (what the user typed)
- escape when you render into HTML

Why?

- you might want to display the raw value in multiple contexts later
- different contexts require different escaping rules

## HTML Escaping with `htmlspecialchars()`

For HTML text contexts, you usually want:

```php
htmlspecialchars($value, ENT_QUOTES, 'UTF-8')
```

In our project we wrap this in a helper function:

- `h()` in `class-10/course-registration/app/lib/functions.php`

Example:

```php
<td><?php print h($studentName); ?></td>
```

This converts characters like:

- `<` to `&lt;`
- `>` to `&gt;`
- `"` to `&quot;`
- `'` to `&#039;`

So the browser displays the text instead of treating it as markup.

## Where You Need Escaping in This Project

Common places:

1. Table cells showing user-entered data (student name, email, course titles)
2. Form field values (edit forms and sticky forms)
3. Query string values you display back to the user

Examples:

```php
<input name="title" value="<?php print h($title); ?>">
```

```php
<code><?php print h($code); ?></code>
```

## Not Everything Is a String

Even though form data begins as strings, our stored JSON has booleans and integers too.

Pattern:

- normalize to a safe string for output
- then escape the string

Example:

```php
<?php
$credits = (int) ($course['credits'] ?? 0);
print $credits; // numbers are safe to print directly
```

But if you build a string:

```php
<?php
$label = $code . ' - ' . $title;
print h($label);
```

## `filter_input()` Is Not Output Escaping

`filter_input()` helps you retrieve request data safely and consistently.

It does **not** make the value safe to print into HTML.

You still must escape when rendering.

## Avoid "HTML in Strings"

When learning, it's easy to do:

```php
print '<p>' . $studentName . '</p>';
```

If you do, you must remember to escape:

```php
print '<p>' . h($studentName) . '</p>';
```

In this course we prefer a template style that keeps HTML visible and uses `<?php print ... ?>` in place,
which makes it harder to forget escaping.

## A Quick Checklist

When you are about to print a variable into an HTML page, ask:

- Did this value come from a user (directly or indirectly)?
- Am I placing it into HTML text or an HTML attribute?
- Did I escape it with `h()`?
