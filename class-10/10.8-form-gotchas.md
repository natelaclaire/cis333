# 10.8 Form Gotchas (Checkboxes, Missing Keys, Arrays, Types)

By now we've built several working forms:

- creating/editing/deleting courses
- creating and removing registrations

This tutorial is a "gotchas" deep dive: issues you will hit constantly when processing form data.

## Gotcha 1: Missing Keys Are Normal

When an input is not submitted, it often does **not** appear in the request data at all.

Examples:

- unchecked checkboxes
- a `<select>` that had no selection (depending on markup)
- a radio group where nothing was chosen

If you assume every key exists, you'll end up with notices/warnings (or bugs).

In this course, we prefer:

- `filter_input()` / `filter_input_array()`
- default values (`postString('department', 'CIS')`)

## Gotcha 2: Checkboxes (Single) Are Special

Checkbox behavior:

- checked: the browser sends the key (usually with value `"1"` or `"on"`)
- unchecked: the browser usually sends **nothing** for that key

So, treat a checkbox as "present or not":

```php
<?php
// Checked? yes/no.
$active = postBool('active');
```

Do not treat it like a required string.

## Gotcha 3: Checkbox Arrays Need `[]` and Array Filtering

If you want multiple checkboxes to create an array in PHP, the name must end with `[]`:

```html
<input type="checkbox" name="meetingDays[]" value="mon">
<input type="checkbox" name="meetingDays[]" value="wed">
```

Then retrieve it as an array:

```php
<?php
$meetingDays = postArray('meetingDays'); // [] if missing

// Optional: filter out non-strings / empty values.
$meetingDays = array_values(array_filter(
    $meetingDays,
    fn ($day) => is_string($day) && $day !== ''
));
```

## Gotcha 4: Every Form Value Starts as a String

Even if the input is numeric (like credits), the browser sends text.

So you often need to cast:

```php
<?php
$credits = (int) postString('credits', '3');
```

Be careful: casting does not validate intent. For example:

- `"3"` becomes `3`
- `"3abc"` becomes `3`
- `"abc"` becomes `0`

We are intentionally deferring full validation to next week (Chapter 12), but keep this behavior in mind.

## Gotcha 5: Radio Buttons and Defaults

Radio buttons behave like selects:

- if the user chose one, you get a string value
- if they chose none, the key may be missing

So use a default:

```php
<?php
$delivery = postString('delivery', 'in_person');
```

In the edit form, pre-fill by conditionally adding `checked`.

## Gotcha 6: `<select>` Values Should Be Treated Like IDs

Our registration form uses:

- `<select name="courseId">` where the option values are course IDs

That means:

- you must verify the chosen ID exists
- you should never "trust" the label text in the HTML

Even this week (light validation), we do a simple integrity check:

```php
<?php
$courseExists = false;
foreach ($data['courses'] as $course) {
    if (is_array($course) && ($course['id'] ?? null) === $courseId) {
        $courseExists = true;
        break;
    }
}
```

## Gotcha 7: Hidden Inputs Are Convenient (But Not Trusted)

We use hidden inputs for IDs in update/delete forms:

```html
<input type="hidden" name="id" value="c_abc123">
```

Hidden inputs are not secure; the browser can modify them.

So the handler must still:

- check that the ID is present
- check that the record exists
- handle "not found" cleanly

## Gotcha 8: PRG Avoids Accidental Double Submits

Any time you process a POST, prefer:

1. process POST
2. `303` redirect to a GET page
3. show a success banner on the GET page via a query string flag (`?created=1`)

This prevents browser refresh from re-submitting the POST.

## `filter_input()` Quick Notes

`filter_input()` returns:

- `null` when the key is missing
- `false` when the filter fails (depending on filter)
- otherwise a string (or an array if you used `FILTER_REQUIRE_ARRAY`)

In our helpers:

- `postString()` defaults missing/false to a safe default string
- `postBool()` treats checkbox presence as `true`
- `postArray()` returns `[]` when missing

Next, we'll focus on safe rendering (escaping) patterns so that user input is displayed safely in HTML.
