# 13.4 Class 13 Reinforcement Exercises

## Exercise 13-1: Building a Login System with PHP Sessions

In this exercise, we’ll build a simple **login system** that uses PHP **sessions** to remember who’s logged in — and display a personalized welcome page. This demonstration will help you understand how session management powers secure, stateful web applications.

### **Project Overview**

Here’s what we’ll build:

1. A **login form** that collects a username and password.
2. A **PHP script** that checks those credentials.
3. A **session** to remember the user after login.
4. A **personalized welcome page**.
5. A **logout page** that ends the session.

We’ll keep the credentials simple — no database — just an associative array in PHP.

### **Step 1: Creating the Login Form**

Let’s start with a file named `13-1-login.php` in the `app/views/pages/exercises` folder. The file will be loaded by our router, so we can access it at `/ex/13-1`.

At the very beginning of each PHP file that will use sessions, we need to call `session_start()`. This initializes the session and allows us to use the `$_SESSION` superglobal array to store and retrieve session data. For practice, we’ll add `session_start()` at the top of each relevant file, but in a real application, you might want to include it in a common header or router file.

We are implementing a flash message system to provide feedback to the user. On the login page, we check for this flash message, display it if it exists, and then immediately unset it so that it only appears once. We'll see this in practice in step 3.

Add the following code to create a basic login form:

```php
session_start();

$username = "";

if ($_SERVER["REQUEST_METHOD"] === "POST") {
  // TODO: Add authentication logic (POST handler) here in step 2
}

$flashError = $_SESSION["flash_error"] ?? "";
unset($_SESSION["flash_error"]);
?>
<div class="container mt-5" style="max-width: 480px;">
  <h2 class="mb-4">Login</h2>
  <?php if ($flashError): ?>
    <div class="alert alert-warning" role="alert"><?php echo htmlspecialchars($flashError); ?></div>
  <?php endif; ?>
  <form method="post" action="/ex/13-1">
    <div class="mb-3">
      <label for="username" class="form-label">Username</label>
      <input type="text" class="form-control" id="username" name="username" value="<?php echo htmlspecialchars($username); ?>" required>
    </div>
    <div class="mb-3">
      <label for="password" class="form-label">Password</label>
      <input type="password" class="form-control" id="password" name="password" required>
    </div>
    <button type="submit" class="btn btn-primary">Login</button>
  </form>
</div>
```

This form sends the username and password to the same route in a POST request, which we’ll handle next.

### **Step 2: Authenticating the User**

After the TODO comment in the code above, we’ll add logic to check the submitted username and password against a hardcoded list of users. If the credentials are correct, we’ll store the username in the session and redirect to a welcome page. Add the following code to handle the POST request:

```php
// Sample user data (this would normally come from a database)
$users = [
  "alex" => "pass123",
  "jordan" => "code456"
];

// using the postString() helper function from our functions.php
$username = postString("username") ?? "";
$password = postString("password") ?? "";

if (isset($users[$username]) && $users[$username] === $password) {
  session_regenerate_id(true);
  $_SESSION["username"] = $username;
  header("Location: /ex/13-1/welcome", true, 303);
  exit();
} else {
  $_SESSION["flash_error"] = "Invalid username or password. Please try again.";
}
?>
```

Here, we check whether the submitted username exists in our array and whether the password matches. If it does, we store the username in `$_SESSION` — that’s what identifies the user across pages — and then redirect with `303` to `/ex/13-1/welcome`. Otherwise, we store a flash error in the session and display the login page again. The flash message is displayed once and then cleared. We don't technically need to store the message in the session since we aren't redirecting back to the login page, but this allows us to piggyback on the session-based flash message system we are implementing for step 3.

### **Step 3: Creating the Personalized Page**

Now, let’s create a personalized page that greets the logged-in user. Open `app/views/pages/exercises/13-1-welcome.php` and add the following code:

```php
session_start();

if (!isset($_SESSION["username"])) {
  $_SESSION["flash_error"] = "You must log in to view that page.";
  header("Location: /ex/13-1", true, 303);
  exit();
}
?>
<div class="container mt-5" style="max-width: 480px;">
  <h2 class="mb-4">Welcome, <?php echo htmlspecialchars($_SESSION["username"]); ?>!</h2>
  <p>You are now logged in.</p>
  <p><a href="/ex/13-1/logout">Logout</a></p>
</div>
```

Here, we first check if `$_SESSION["username"]` is set. If not, we set a flash error and redirect back to the login route with `303`, which avoids rendering protected content and provides clear feedback on the next request. Otherwise, we safely display the username and a logout link.

### **Step 4: Logging Out**

Finally, we’ll let users log out by ending the session. Open the `app/views/pages/exercises/13-1-logout.php` file and add this code:

```php
session_start();

$_SESSION = [];

if (ini_get("session.use_cookies")) {
    $params = session_get_cookie_params();
    setcookie(session_name(), '', time() - 42000,
        $params["path"], $params["domain"],
        $params["secure"], $params["httponly"]
    );
}

session_destroy();

header("Location: /ex/13-1", true, 303);
exit();
```

When the user clicks “Logout,” this script clears all session data and redirects them back to the login page.

### **Step 5: Testing the System**

Let’s test it out.

1. Start Apache if it isn't already and then use the Ports tab to connect to the port and click the link to exercise 13-1.
2. Enter a valid username and password — “alex” and “pass123.”
3. You’ll be redirected to `/ex/13-1/welcome`, where your username appears.
4. Click “Logout,” and the session data is gone — try reloading `/ex/13-1/welcome`, and you’ll be redirected to the login page again with the flash error message.

## Exercise 13-2: Playing with Cookies

In this exercise, you will create a simple PHP application that uses cookies to remember a user's preferred background color for the webpage.

### **Project Overview**

Here’s what we’ll build:

1. A form where users can select their preferred background color.
2. A PHP script to save this preference in a cookie.
3. A way to read the cookie and apply the background color when the user returns.

### **Step 1: Creating the Color Selection Form**

Open the `app/views/pages/exercises/13-2-color-preference.php` file and review the existing form code. This form allows users to select a background color from a dropdown menu and submit their choice. The form also includes a "Reset to Default" button that will clear the cookie and reset the background color to white. The form submits a POST request to the same page, which we will handle in the next step. The background color is applied to the form itself for immediate feedback, and the selected color is preserved in the dropdown after submission.

### **Step 2: Saving the Color Preference in a Cookie**

Add the following PHP code at the TODO in `13-2-color-preference.php` to handle form submissions and set the cookie:

```php
    if (isset($_POST["reset"])) {
        setcookie("bgcolor", "", time() - 3600, "/");
        header("Location: /ex/13-2", true, 303);
        exit();
    }

    $color = filter_input(INPUT_POST, "color", FILTER_SANITIZE_SPECIAL_CHARS) ?? "white";
    if (!in_array($color, $allowedColors, true)) {
        $color = "white";
    }

    setcookie("bgcolor", $color, time() + 86400, "/");
    header("Location: /ex/13-2", true, 303);
    exit();
```

### **Step 3: Applying the Background Color to the Page from the Cookie (Optional)**

As noted, the background color is currently applied only to the form itself. To apply the background color to the entire page from the cookie, add the following code after the form handling logic:

```php
<?php
echo "<style>body { background-color: $bgcolor; }</style>";
?>
```

This should technically go in the `<head>` section of the HTML document for best practices, but for simplicity, we can include it here. This code will read the `bgcolor` cookie and apply it as the background color for the entire page.

### **Step 4: Testing the Application**

1. Use the link from the home page to open `/ex/13-2` in your browser.
2. Select a background color from the dropdown and submit the form.
3. Refresh the page, and you should see the selected background color applied.
4. Close the browser and reopen it to see if the color preference persists (it should, as long as the cookie hasn't expired).
5. Try changing the color again to see how the cookie updates.

## Exercise 13-4: Guessing Game

You can use PHP’s rand() function to generate a random integer. The `rand()` function accepts two arguments that specify the minimum and maximum integer to generate, respectively. For example, the statement `$randNum = rand(10, 20)` generates a random integer between 10 and 20 and assigns the number to the `$randNum` variable. Create a guessing game that uses sessions to store a random number between 0 and 100, along with the number of guesses the user has attempted. Each time the user guesses wrong, display the number of times the user has guessed. Include a Give Up link that displays the generated number for the current game. Also include a Start Over link that deletes the user session and uses the `header("location:URL")` function to navigate to the main page. All of this logic should be implemented in a single PHP file named `13-4-guessing-game.php` in the `app/views/pages/exercises` folder, using a POST handler, query string parameters, and sessions to manage the game state and trigger logic.

### **Step 2: Creating the Product Detail Page**

Open the `13-5-product-details.php` file in the same folder. On your own, implement the following:
