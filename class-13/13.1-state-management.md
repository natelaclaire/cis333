# 13.1 Managing State in PHP

When you click a link or submit a form on a website, your browser sends a request to a web server — and the server responds. That’s it. Once the response is delivered, the connection is closed and the server forgets everything about you.

That’s because **HTTP is a stateless protocol.** Each request is completely independent — the server doesn’t automatically remember who you are or what you were doing before.

This stateless nature makes the web simple and efficient, but it creates a challenge for developers: How do we make a user’s experience feel continuous — like they’re “logged in,” “shopping,” or “in the middle of a game”?

That’s where **state management** comes in.

---

## 🔹 **1. Hidden Form Fields**

One of the simplest ways to maintain state is with **hidden form fields**, as we've done to store the ID field on a few edit forms over the past few weeks. These are invisible inputs that store data within an HTML form — like a username or game score — and get resubmitted each time the form is posted.

It’s a good solution for small, short-lived data, but because the data travels with every form submission, it’s not ideal for sensitive information or larger datasets.

---

## 🔹 **2. Query Strings**

Another approach is using **query strings**, which attach information to the end of a URL. We're used these a lot in various projects.

Unlike hidden fields, query strings make state visible to the user — which is both an advantage and a security concern.

---

## 🔹 **3. Cookies**

To persist information beyond a single request, we can use **cookies**. A cookie is a small piece of data stored in the user’s browser and automatically sent back to the server with each request.

You can set a cookie in PHP with the `setcookie()` function, and read it with the `$_COOKIE` superglobal array. Cookies are great for remembering user preferences or keeping someone logged in — but they live on the client side, so they can be modified or deleted by the user.

---

## 🔹 **4. Sessions**

To store data securely on the server, we use **sessions**. A session assigns a unique session ID to each visitor, usually stored in a small cookie although it can instead be passed as a query parameter. The actual data — like user credentials or cart contents — stays on the server.

In PHP, sessions are easy to use:

```php
session_start();
$_SESSION['username'] = 'alex';
```

Sessions are the backbone of most modern PHP applications because they keep data safe and separate from the client.

---

## 🔹 **5. Modern State Management (2026 and Beyond)**

Over the past several years, web applications have evolved — and so have the ways we manage state. Frameworks and APIs often use:

* **JWTs (JSON Web Tokens):** for stateless authentication between frontend and backend.
* **LocalStorage and SessionStorage:** browser-based storage managed by JavaScript, ideal for single-page apps.
* **Redis or Memcached:** in-memory data stores for high-performance session management in scalable PHP applications.

These tools allow PHP to integrate smoothly into modern, cloud-based and API-driven architectures. And yet, we still use hidden form fields, query string parameters, cookies, and sessions extensively.

---

## 🔹 **Conclusion**

So while HTTP itself forgets every request, PHP gives us plenty of ways to bridge the gap — from hidden fields and query strings to cookies and sessions. Understanding these tools is essential for building dynamic, personalized, and secure web applications.
