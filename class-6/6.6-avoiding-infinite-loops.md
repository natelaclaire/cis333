# 6.6 Avoiding Infinite Loops

An infinite loop happens when the loop condition never becomes false (or when
you intentionally use `while (true)` without a reachable `break`). Infinite
loops can hang your script, spam output, or consume CPU.

## Common Causes

- Forgetting to update the loop control variable
- Updating the wrong variable
- A condition that can never become false
- Input that never changes (for example, always failing validation)

## The First Fix: Make Progress Every Iteration

If your condition depends on a variable, make sure that variable changes.

```php
<?php
$count = 1;

while ($count <= 3) {
    print 'count: ' . $count . PHP_EOL;
    $count++;
}
?>
```

## Add a Guardrail (Max Iterations)

When you are experimenting or debugging, add a hard stop so mistakes do not
run forever.

```php
<?php
$count = 1;
$maxIterations = 10;

while ($count <= 1000) {
    print 'count: ' . $count . PHP_EOL;
    $count++;

    if ($count > $maxIterations) {
        print 'stopping early (debug guardrail)' . PHP_EOL;
        break;
    }
}
?>
```

## Use `while (true)` Only With a Clear Exit

`while (true)` is fine when the exit logic is explicit and easy to see.

```php
<?php
while (true) {
    $input = readline('Enter a number (or q): ');
    if ($input === false) {
        $input = '';
    }

    $input = trim($input);
    if ($input === 'q') {
        break;
    }

    if (!is_numeric($input)) {
        print 'Not numeric' . PHP_EOL;
        continue;
    }

    $value = (float) $input;
    print 'value: ' . $value . PHP_EOL;
}
?>
```

## Debugging Pattern: Print the State

If you do not understand why a loop is not ending, print the values that
control the loop.

```php
<?php
$count = 1;

while ($count <= 3) {
    print 'debug count=' . $count . PHP_EOL;
    $count++;
}
?>
```

The goal is to make it obvious how the loop variable changes and why the
condition should eventually become false.
