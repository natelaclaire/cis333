# 5.1 Separating Code into Multiple Files

In this video, we cover how to split PHP into multiple files with `include`,
`require`, and the `*_once` variants. This is the foundation for organizing
projects and reusing functions across scripts.

## Why Split Code Into Files

Separating code helps you:

- Reuse functions across multiple scripts
- Keep files smaller and easier to read
- Avoid copy/paste duplication

## `include` vs `require`

Both statements pull another file into the current script.

- `include` raises a warning if the file is missing and continues.
- `require` triggers a fatal error if the file is missing and stops.

```php
<?php
include 'optional-banner.php';
print 'Page continues even if include fails.' . PHP_EOL;
?>
```

```php
<?php
require 'required-config.php';
print 'This line only runs if the file was found.' . PHP_EOL;
?>
```

## `include_once` and `require_once`

If a file might be loaded more than once (for example, a file full of
function declarations), use `*_once` to avoid redeclare errors.

```php
<?php
require_once __DIR__ . '/lib/functions.php';
require_once __DIR__ . '/lib/functions.php';

print 'Loaded functions once.' . PHP_EOL;
?>
```

## Path Best Practice: Use `__DIR__`

When you use a relative path like `'lib/functions.php'`, it can behave
differently depending on the current working directory. A common pattern is
to build an absolute path from the `__DIR__` magic constant instead. The
`__DIR__` constant gives you the directory of the current file, so you can
reliably include files relative to it:

```php
<?php
require_once __DIR__ . '/lib/functions.php';
?>
```

This makes your includes predictable no matter where the script is run from.
