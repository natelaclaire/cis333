# 5.5 Multiple Types and `strict_types`

In this video, we look at type declarations for parameters and return values,
including union types. We'll also discuss `strict_types` and how it changes
type coercion behavior.

## Union Types

Union types let a parameter (or return value) accept more than one type.

```php
<?php
function stringify(int|string $value): string
{
    return (string) $value;
}

print stringify(42) . PHP_EOL;
print stringify('42') . PHP_EOL;
?>
```

## Multiple Return Types

Sometimes a function might return one of a few types depending on input.

```php
<?php
function parseCount(string $input): int|false
{
    if (ctype_digit($input)) {
        return (int) $input;
    }

    return false;
}

$count = parseCount('12');
print 'count: ' . $count . PHP_EOL;
?>
```

## `mixed` (Use Sparingly)

`mixed` accepts any type, which can be useful, but it removes a lot of type
clarity. Prefer specific types or a union when you can.

```php
<?php
function debugValue(mixed $value): void
{
    var_dump($value);
}

debugValue(['a' => 1]);
?>
```

## `declare(strict_types=1);`

By default, PHP may coerce values to match parameter types. With
`strict_types`, PHP requires arguments to match the declared types.

```php
<?php
declare(strict_types=1);

function multiply(int $a, int $b): int
{
    return $a * $b;
}

print multiply(4, 5) . PHP_EOL;
?>
```

If you try `multiply(4, '5')` with `strict_types=1`, PHP throws a `TypeError`
instead of converting the string to an integer.
