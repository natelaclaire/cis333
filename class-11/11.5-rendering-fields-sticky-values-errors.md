# 11.5 Rendering Fields (Sticky Values + Errors + Safe Escaping)

In 11.4 we designed a field spec array so our form has “one source of truth”.

Now we use that spec to render HTML consistently:

- labels and inputs
- sticky values (what the user typed)
- per-field error messages
- safe output escaping (XSS prevention)

This is where forms stop feeling like copy/paste and start feeling like a system.

## Goal: Templates Should Be Boring

When your templates are “boring”:

- they’re easier to review
- they’re harder to break
- you’re less likely to forget escaping or error output

So we’ll push complexity into a small set of helper functions.

## Inputs Are Untrusted: Escape on Output

Any value that came from the request (even after sanitization) must be treated as untrusted when rendering HTML.

We will use an `h()` helper:

```php
<?php
function h(string $value): string
{
    return htmlspecialchars($value, ENT_QUOTES, 'UTF-8');
}
```

Rule:

- Every time you print a string into HTML, wrap it in `h(...)`.

## A Simple Rendering Strategy

We’ll assume we have:

- `$fields` (the spec array)
- `$values` (sticky values)
- `$errors` (per-field error messages; `''` means no error)

Example shapes:

```php
<?php
$values = [
    'applicantName' => 'Ada Lovelace',
    'contactEmail' => 'ada@example.com',
];

$errors = [
    'applicantName' => '',
    'contactEmail' => 'Email is required.',
];
```

## Rendering HTML Attributes from an Array

We often want to convert:

```php
['required' => true, 'maxlength' => 120, 'autocomplete' => 'email']
```

into:

```html
required maxlength="120" autocomplete="email"
```

Helper function:

```php
<?php
function renderAttrs(array $attrs): string
{
    $out = [];
    foreach ($attrs as $key => $value) {
        if (!is_string($key) || $key === '') {
            continue;
        }

        if ($value === true) {
            $out[] = h($key);
            continue;
        }

        if ($value === false || $value === null) {
            continue;
        }

        $out[] = h($key) . '="' . h((string) $value) . '"';
    }

    return implode(' ', $out);
}
```

Notes:

- boolean attributes like `required` should render as `required`
- all attribute values must be escaped

## Rendering an Error Message Block

Helper:

```php
<?php
function renderError(string $name, array $errors): string
{
    $message = $errors[$name] ?? '';
    if (!is_string($message) || $message === '') {
        return '';
    }

    return '<div class="invalid-feedback d-block">' . h($message) . '</div>';
}
```

We use Bootstrap’s `invalid-feedback` styling here, but the important part is the pattern:

- centralized
- consistent
- always escaped

## Rendering Text-Like Inputs

Most fields can be rendered as a label + input.

Helper:

```php
<?php
function renderInput(array $field, string $name, array $values, array $errors): string
{
    $label = is_string($field['label'] ?? null) ? $field['label'] : $name;
    $type = is_string($field['type'] ?? null) ? $field['type'] : 'text';

    $value = $values[$name] ?? '';
    $value = is_string($value) ? $value : '';

    $attrs = is_array($field['html'] ?? null) ? $field['html'] : [];
    $attrs['name'] = $name;
    $attrs['id'] = $name;
    $attrs['type'] = $type;
    $attrs['value'] = $value;

    $hasError = ($errors[$name] ?? '') !== '';
    if ($hasError) {
        $attrs['aria-invalid'] = 'true';
    }

    $class = 'form-control';
    if ($hasError) {
        $class .= ' is-invalid';
    }

    $attrsText = renderAttrs($attrs);

    $html = '';
    $html .= '<label class="form-label" for="' . h($name) . '">' . h($label) . '</label>';
    $html .= '<input class="' . h($class) . '" ' . $attrsText . '>';
    $html .= renderError($name, $errors);
    return $html;
}
```

Important ideas:

- sticky values come from `$values`, not from the field spec
- error state affects both styling and accessibility (`aria-invalid`)
- values and labels are escaped on output

## Rendering a Textarea

Textareas do not use a `value=""` attribute. The value is inside the element.

Helper:

```php
<?php
function renderTextarea(array $field, string $name, array $values, array $errors): string
{
    $label = is_string($field['label'] ?? null) ? $field['label'] : $name;
    $value = $values[$name] ?? '';
    $value = is_string($value) ? $value : '';

    $attrs = is_array($field['html'] ?? null) ? $field['html'] : [];
    $attrs['name'] = $name;
    $attrs['id'] = $name;

    $hasError = ($errors[$name] ?? '') !== '';
    if ($hasError) {
        $attrs['aria-invalid'] = 'true';
    }

    $class = 'form-control';
    if ($hasError) {
        $class .= ' is-invalid';
    }

    $attrsText = renderAttrs($attrs);

    $html = '';
    $html .= '<label class="form-label" for="' . h($name) . '">' . h($label) . '</label>';
    $html .= '<textarea class="' . h($class) . '" ' . $attrsText . '>' . h($value) . '</textarea>';
    $html .= renderError($name, $errors);
    return $html;
}
```

## Rendering Selects and Radios (Options)

For a select or radio group, we need:

- an option list
- a selected value (sticky)
- server-side validation to ensure the submitted value is allowed

For now, we’ll keep this simple:

- spec contains `options` (value => label)
- the renderer marks the matching option as `selected` or `checked`

## Rendering a Checkbox (Boolean)

Checkbox sticky values are not strings; treat them as boolean.

Typical patterns:

- checked if the stored value is true
- otherwise unchecked

And remember:

- unchecked checkboxes are often missing from the request
- your retrieval layer should map “present” to `true` and “missing” to `false`
