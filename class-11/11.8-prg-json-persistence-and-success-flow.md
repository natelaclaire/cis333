# 11.8 PRG + JSON Persistence (Save Valid Submissions)

At this point in the week, we have the pieces for robust form handling:

- a field spec (one source of truth)
- a rendering layer (sticky values + per-field errors + escaping)
- a validation engine (server-side truth)
- a clear separation between sanitization/normalization and escaping

Now we wire it into a complete, user-friendly flow:

- show the form (GET)
- process the submission (POST)
- if errors: re-render the form (sticky + errors)
- if valid: save to a JSON file and redirect (PRG)
- show a success message on the GET request

## Why PRG Matters Here

If you process a POST and then immediately output HTML, the browser’s refresh button can re-submit the POST.

PRG (Post-Redirect-Get) avoids this:

1. user submits POST
2. server saves the data
3. server responds with a redirect (usually `303`)
4. browser follows the redirect with a GET

Refreshing the GET page does **not** re-submit the POST.

## JSON Persistence: A Simple Data Store

For this week’s grant application, we’ll store validated submissions in a JSON file.

Example shape:

```json
{
  "applications": [
    {
      "id": "ga_abc123",
      "createdAt": "2026-04-04T14:22:31-04:00",
      "applicantName": "Ada Lovelace",
      "contactEmail": "ada@example.com",
      "organizationName": "Analytical Engines for All",
      "requestedAmount": 1500,
      "category": "education",
      "projectSummary": " ... ",
      "websiteUrl": "https://example.org",
      "agreeToTerms": true
    }
  ]
}
```

Key principle:

- **Only save after validation passes.**

## A Safe Save Pattern (Atomic Write)

When writing JSON, avoid partially-written files by using an atomic write pattern:

- encode JSON
- write to a temporary file with `LOCK_EX`
- `rename()` the temp file into place

Example:

```php
<?php
function saveJsonFile(string $path, array $data): bool
{
    $json = json_encode($data, JSON_PRETTY_PRINT);
    if ($json === false) {
        return false;
    }

    $tmp = $path . '.tmp';
    $bytes = file_put_contents($tmp, $json . "\n", LOCK_EX);
    if ($bytes === false) {
        return false;
    }

    return rename($tmp, $path);
}
```

## A Minimal Controller Flow (GET + POST)

Here is the high-level shape we want in our grant application page:

```php
<?php
// 1) define $fields spec
// 2) init $values/$errors from defaults
// 3) on POST:
//    - read/sanitize/normalize values
//    - validate into $errors
//    - if valid: save + redirect (303)
// 4) on GET:
//    - render form (and optionally show ?success=1 banner)
```

Example:

```php
<?php
[$values, $errors] = initValuesAndErrors($fields);

if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    $values = readValues($fields);          // filter_input + basic normalization
    $errors = validateValues($fields, $values); // rules -> errors

    if (!hasErrors($errors)) {
        $data = loadData(); // load JSON into an array

        $application = buildApplicationRecord($values);
        $data['applications'][] = $application;

        saveData($data);

        header('Location: /grant?success=1', true, 303);
        exit;
    }
}

$success = ($_GET['success'] ?? '') === '1';
renderGrantForm($fields, $values, $errors, $success);
```

Notes:

- this shows the PRG pattern explicitly
- the form is sticky when validation fails (same page re-renders)
- the success message is shown on GET via a query string flag

In our implementation, we’ll prefer `filter_input()` over reading `$_GET` / `$_POST` directly.

## What to Save (Raw vs Typed Values)

Your rendered form values are usually strings.
But what you persist should follow business meaning:

- store requestedAmount as an integer (if that’s the rule)
- store agreeToTerms as a boolean

That suggests a “build record” step:

```php
<?php
function buildApplicationRecord(array $values): array
{
    return [
        'id' => 'ga_' . bin2hex(random_bytes(6)),
        'createdAt' => date(DATE_ATOM),
        'applicantName' => (string) ($values['applicantName'] ?? ''),
        'contactEmail' => (string) ($values['contactEmail'] ?? ''),
        'organizationName' => (string) ($values['organizationName'] ?? ''),
        'requestedAmount' => (int) ($values['requestedAmount'] ?? 0),
        'category' => (string) ($values['category'] ?? ''),
        'projectSummary' => (string) ($values['projectSummary'] ?? ''),
        'websiteUrl' => (string) ($values['websiteUrl'] ?? ''),
        'agreeToTerms' => (bool) ($values['agreeToTerms'] ?? false),
    ];
}
```
