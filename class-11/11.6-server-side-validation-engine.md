# 11.6 Server-Side Validation Engine (Rules + Errors)

In 11.4 we created a field spec (one source of truth).
In 11.5 we built rendering patterns for sticky values + per-field errors.

Now we build the missing piece: a server-side validation engine that takes:

- the field spec (`$fields`)
- the request data (via `filter_input()`)

and produces:

- `$values` (normalized, sticky values)
- `$errors` (per-field error messages)

This is the core of Chapter 12: server-side validation is the source of truth.

## Output of the Validator

We’ll standardize on these shapes:

```php
<?php
$values = []; // string/bool/array values ready to re-render (sticky)
$errors = []; // string messages; '' means no error for that field
```

And a helper to check “any errors?”:

```php
<?php
function hasErrors(array $errors): bool
{
    foreach ($errors as $message) {
        if (is_string($message) && $message !== '') {
            return true;
        }
    }
    return false;
}
```

## Step 1: Initialize Defaults

Before reading a request, initialize values + errors from the spec:

```php
<?php
function initValuesAndErrors(array $fields): array
{
    $values = [];
    $errors = [];

    foreach ($fields as $name => $field) {
        if (!is_string($name) || !is_array($field)) {
            continue;
        }

        $values[$name] = $field['default'] ?? '';
        $errors[$name] = '';
    }

    return [$values, $errors];
}
```

This guarantees your templates can always read `$values[$name]` and `$errors[$name]` without undefined index
notices.

## Step 2: Retrieve + Sanitize Values

We retrieve values based on type/spec.

Common cases:

- text/email/url/textarea/select/radio => string
- checkbox => boolean (present or not)
- checkbox arrays (`tags[]`) => array

Conceptual retrieval:

```php
<?php
function readValue(string $name, array $field)
{
    $type = is_string($field['type'] ?? null) ? $field['type'] : 'text';

    if ($type === 'checkbox') {
        return filter_input(INPUT_POST, $name, FILTER_UNSAFE_RAW) !== null;
    }

    if ($type === 'checkboxes') {
        $arr = filter_input(INPUT_POST, $name, FILTER_UNSAFE_RAW, FILTER_REQUIRE_ARRAY);
        return is_array($arr) ? $arr : [];
    }

    $sanitize = $field['sanitize']['filter'] ?? FILTER_UNSAFE_RAW;
    $value = filter_input(INPUT_POST, $name, $sanitize);
    return is_string($value) ? $value : '';
}
```

In our project we will likely wrap this in a `readValues($fields)` function.

## Step 3: Normalize Values

Before validating, normalize into predictable shapes.

Examples:

- `trim()` strings
- cast numbers
- ensure arrays are arrays

This reduces edge cases inside rules.

Example:

```php
<?php
if (is_string($value)) {
    $value = trim($value);
}
```

## Step 4: Apply Rules and Build Error Messages

Each field spec includes `rules`.

We’ll implement a few common rules for the grant application:

- `required`
- `minLength` / `maxLength`
- `email` (validate email format)
- `url` (validate URL format)
- `intRange` (validate integer and range)
- `in` (allowed values)
- `requiredTrue` (checkbox must be checked)

### Required (string)

```php
<?php
if (($rules['required'] ?? false) === true && $value === '') {
    $errors[$name] = $label . ' is required.';
}
```

### Required true (checkbox)

```php
<?php
if (($rules['requiredTrue'] ?? false) === true && $value !== true) {
    $errors[$name] = 'You must agree to the terms.';
}
```

### Min/max length

```php
<?php
$len = strlen($value);
if (isset($rules['minLength']) && $len < (int) $rules['minLength']) {
    $errors[$name] = $label . ' must be at least ' . (int) $rules['minLength'] . ' characters.';
}
if (isset($rules['maxLength']) && $len > (int) $rules['maxLength']) {
    $errors[$name] = $label . ' must be at most ' . (int) $rules['maxLength'] . ' characters.';
}
```

### Email format

```php
<?php
if (($rules['email'] ?? false) === true && $value !== '') {
    if (filter_var($value, FILTER_VALIDATE_EMAIL) === false) {
        $errors[$name] = $label . ' must be a valid email address.';
    }
}
```

### Allowed values (`in`)

```php
<?php
$allowed = $rules['in'] ?? null;
if (is_array($allowed) && $value !== '' && !in_array($value, $allowed, true)) {
    $errors[$name] = $label . ' must be one of the allowed values.';
}
```

## Rule Ordering Matters

If a field is required and missing, you often want the “required” message to win.

That means:

- check `required` first
- only run deeper checks if there is no error yet

Pattern:

```php
<?php
if ($errors[$name] === '') {
    // run the next rule...
}
```

## Validated Values vs Sticky Values

One subtlety:

- sticky values are what the user typed (for re-rendering)
- validated values may be transformed (casting int/float)

In many apps, we store both:

- `$values` (strings for display)
- `$validated` (typed values for persistence)

For this week’s project, we’ll keep it simple and aim for:

- `$values` as normalized values that are safe to re-render
- then build a submission record from `$values` when there are no errors
