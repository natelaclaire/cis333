# 11.2 `filter_input()` Deep Dive (Validation + Sanitization Filters)

In 11.1 we focused on the validation mindset and the trust boundary.

Now we’re going to focus on *how to retrieve request data* in PHP using the filter API.

Chapter 12 uses PHP’s filtering functions heavily. This tutorial also extends the chapter by surveying the most
useful **sanitization filters** you can apply via `filter_input()`.

## The Three Related Functions

PHP’s filter API gives you three commonly used functions:

- `filter_input()` retrieves a value from the request and filters it.
- `filter_input_array()` retrieves multiple values at once.
- `filter_var()` filters a variable you already have in PHP (not tied to the request).

There is also:

- `filter_has_var()` which checks whether a key exists in the external input.

For this class, the main focus is `filter_input()` and `filter_input_array()`.

## `filter_input()` Signature (Conceptually)

```php
<?php
$value = filter_input(
    INPUT_POST,         // where to read from: INPUT_GET, INPUT_POST, INPUT_COOKIE, etc.
    'email',            // key name
    FILTER_SANITIZE_EMAIL, // filter type
    []                  // optional options/flags
);
```

## Return Values: `null` vs `false` vs “a value”

One of the most important details is what `filter_input()` returns:

- `null` if the key does not exist in the request
- `false` if the filter fails (for validation filters, depending on filter/options)
- otherwise, it returns the filtered value (usually a string)

This leads to a common best practice:

- use strict comparisons (`=== false`) when checking for validation failures

## Validation Filters vs Sanitization Filters

Remember the distinction:

- **Validation** determines whether a value is acceptable.
- **Sanitization** cleans/normalizes a value, but does not guarantee it is “valid”.

### Example: sanitize then validate (email)

```php
<?php
$email = filter_input(INPUT_POST, 'contactEmail', FILTER_SANITIZE_EMAIL);

// Sanitization is not validation.
if ($email === null || $email === '') {
    $error = 'Email is required.';
} elseif (filter_var($email, FILTER_VALIDATE_EMAIL) === false) {
    $error = 'Email must be a valid email address.';
}
```

## Useful Sanitization Filters (Common Ones)

These are practical filters you’ll see frequently in forms-based apps:

- `FILTER_SANITIZE_EMAIL`
  - removes characters that are not allowed in email addresses
- `FILTER_SANITIZE_URL`
  - removes characters that are not allowed in URLs
- `FILTER_SANITIZE_NUMBER_INT`
  - removes all characters except digits and `+` / `-`
- `FILTER_SANITIZE_NUMBER_FLOAT`
  - removes non-numeric characters; usually combined with flags
- `FILTER_SANITIZE_SPECIAL_CHARS`
  - encodes some special characters (not a replacement for `htmlspecialchars()` in templates)
- `FILTER_UNSAFE_RAW`
  - no filtering; still useful as a consistent retrieval mechanism

Important notes:

- Sanitization can produce an empty string. Treat empty-after-sanitize as invalid for required fields.
- Don’t use sanitization as your only “security step”. You still need output escaping in HTML contexts.

### About `FILTER_SANITIZE_STRING`

Older PHP tutorials often show `FILTER_SANITIZE_STRING`.

It is deprecated in modern PHP versions (PHP 8.1+). Prefer explicit steps instead:

- `trim()` for whitespace
- `strip_tags()` if you want to remove HTML tags
- `htmlspecialchars()` (escape-on-output) when rendering into HTML

## Useful Validation Filters (Common Ones)

These filters answer “is it valid?” questions:

- `FILTER_VALIDATE_EMAIL`
- `FILTER_VALIDATE_INT`
- `FILTER_VALIDATE_FLOAT`
- `FILTER_VALIDATE_URL`
- `FILTER_VALIDATE_BOOLEAN`
- `FILTER_VALIDATE_REGEXP` (with an `options` regex)

### Validating an integer range (and the “0 is valid” gotcha)

`FILTER_VALIDATE_INT` returns:

- the integer value if valid
- `false` if invalid

That means `0` is a valid integer, so you must check with `=== false`:

```php
<?php
$age = filter_input(INPUT_POST, 'age', FILTER_VALIDATE_INT, [
    'options' => [
        'min_range' => 18,
        'max_range' => 99,
    ],
]);

if ($age === false) {
    $error = 'Age must be an integer between 18 and 99.';
}
```

## Using Options and Flags

Many filters accept an `options` array and/or flags.

Example: validating a float with a default:

```php
<?php
$amount = filter_input(INPUT_POST, 'requestedAmount', FILTER_VALIDATE_FLOAT, [
    'options' => [
        'default' => null,
    ],
]);
```

Example: sanitizing a float:

```php
<?php
$amountText = filter_input(INPUT_POST, 'requestedAmount', FILTER_SANITIZE_NUMBER_FLOAT, [
    'flags' => FILTER_FLAG_ALLOW_FRACTION,
]);
```

## Arrays From Forms (Checkbox Groups)

If a form has `name="tags[]"`, PHP can receive an array.

Use `FILTER_REQUIRE_ARRAY`:

```php
<?php
$tags = filter_input(INPUT_POST, 'tags', FILTER_UNSAFE_RAW, FILTER_REQUIRE_ARRAY);
if ($tags === null || $tags === false || !is_array($tags)) {
    $tags = [];
}
```

Then validate the array contents (allowed values, max count, etc.).

## `filter_input_array()` for Bulk Retrieval

When you have many fields, `filter_input_array()` can retrieve them together.

Example:

```php
<?php
$inputs = filter_input_array(INPUT_POST, [
    'contactEmail' => FILTER_SANITIZE_EMAIL,
    'websiteUrl' => FILTER_SANITIZE_URL,
    'requestedAmount' => FILTER_UNSAFE_RAW,
]);

// $inputs is an array (or null). Each key maps to the filtered value.
```

This can reduce repetitive code, but you still need:

- per-field validation logic
- per-field error messages
