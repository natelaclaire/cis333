# 11.3 HTML5 Validation for UX (And Why Server-Side Still Matters)

In 11.2 we focused on server-side retrieval + filtering with `filter_input()`.

In this tutorial we focus on *client-side validation* tools built into HTML5 and why they’re helpful for UX.
We’ll also briefly discuss how JavaScript can enhance validation.

The key idea:

- Client-side validation improves the user experience.
- Server-side validation is still required for correctness and security.

## What Browsers Can Validate for You

Modern browsers can validate many constraints automatically when you use:

- the right input type (`email`, `url`, `number`, `date`)
- validation attributes (`required`, `min`, `max`, `minlength`, `maxlength`, `pattern`)

If a field fails HTML5 constraints, the browser will typically:

- prevent form submission
- show a built-in error message and focus the field

This is great for UX because the user gets immediate feedback.

## Input Types That Help (and Why)

Using the right input type improves both validation and usability:

- `type="email"`
  - browser checks basic email shape
  - mobile devices often show an email-friendly keyboard
- `type="url"`
  - browser checks basic URL shape
- `type="number"`
  - browser gives numeric UI controls
  - supports `min`, `max`, `step`
- `type="date"`
  - browser gives a date picker
- `type="tel"`
  - helps mobile keyboards (but does not validate a phone format by itself)

See [MDN HTML5 input types](https://developer.mozilla.org/en-US/docs/Learn_web_development/Extensions/Forms/HTML5_input_types) for more.

## Common HTML5 Validation Attributes

### `required`

Marks a field as required:

```html
<input type="text" name="applicantName" required>
```

### `minlength` / `maxlength`

Useful for text constraints:

```html
<textarea name="projectSummary" minlength="50" maxlength="1000" required></textarea>
```

### `min` / `max` / `step`

Useful for numeric constraints:

```html
<input type="number" name="requestedAmount" min="100" max="5000" step="1" required>
```

### `pattern`

Validates input with a regular expression (client-side only):

```html
<input
  type="text"
  name="zip"
  pattern="\\d{5}"
  title="Please enter a 5-digit ZIP code"
>
```

Notes about `pattern`:

- It applies to many text-like inputs.
- It’s easy to get wrong.
- It’s not a security feature (users can bypass it).
- If you use it, include a helpful `title` or description so users know the rule.

## What HTML5 Validation Does *Not* Do

HTML5 validation:

- does not protect your server
- does not prevent crafted requests
- does not guarantee your business rules are enforced

Example:

- Your form uses `min="100" max="5000"` for requestedAmount.
- An attacker can still submit `requestedAmount=999999` by crafting a POST request.

So you must validate again on the server.

## JavaScript Validation (Brief)

JavaScript can provide “progressive enhancement”:

- show inline hints while typing
- highlight invalid fields immediately
- disable the submit button until required fields are filled

Example: stop submission if a required field is blank:

```html
<script>
document.querySelector('form')?.addEventListener('submit', (event) => {
  const name = document.querySelector('input[name="applicantName"]')?.value ?? '';
  if (name.trim() === '') {
    event.preventDefault();
    alert('Applicant name is required.');
  }
});
</script>
```

But JavaScript:

- can be disabled
- can be bypassed
- can be modified in DevTools

So it never replaces server-side validation.

## Putting It Together (Our Approach This Week)

We will do both:

1. Add HTML5 attributes to make the form pleasant to use.
2. Implement server-side validation that is the source of truth.

We won't implement JavaScript validation since this isn't a JavaScript course, but it’s a common enhancement for better UX.

In the next tutorial (11.4), we’ll define a “field spec” array that includes both:

- server-side validation rules (required, allowed values, min/max)
- HTML attributes for client-side UX (`required`, `minlength`, `pattern`, etc.)

That keeps our form consistent without copy/paste duplication.
